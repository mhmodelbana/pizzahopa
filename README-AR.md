# هوبا بيتزا — نسخة موحّدة للإنتاج

النسخة دي تحافظ على واجهة المتجر العربية ولوحة الإدارة الحالية، وتضيف مسارًا أكثر أمانًا للطلبات وتتبعها. الحزمة تشمل الواجهة، لوحة الإدارة، بناء CSS، ترحيل قاعدة البيانات، Edge Function، واختبارات تحقق أولية.

## ما الذي تغيّر؟

- تتبّع وتعديل وإلغاء العميل يعتمد على رمز عشوائي 256-bit، ويتم تخزين بصمته SHA-256 في قاعدة البيانات بدل الاعتماد على رقم الطلب ورقم الهاتف فقط.
- إنشاء الطلب يظل يعيد تسعير المنتج والحجم والإضافات من قاعدة البيانات، ويضيف `idempotency_key` لمنع إنشاء طلب مكرر عند إعادة المحاولة بعد انقطاع الاتصال.
- الطلبات العامة تمر من `supabase/functions/hopa-public-api` مع rate limiting من الخادم، والتحقق من Origin، وإمكانية تشغيل Cloudflare Turnstile اختياريًا.
- دوال التتبع القديمة المعتمدة على الهاتف تُمنع عن `anon` و`authenticated` بعد تطبيق ترحيل الحماية، ويُسمح بها لـ `service_role` فقط خلف Edge Function.
- إضافة `order_events` لسجل تغييرات الطلب، ومنع تحديث الحالة مباشرة من جلسة المتصفح، وفرض تدفق الحالات من خلال `admin_set_hopa_order_status`.
- أرقام لوحة التحكم أصبحت تجميعات من قاعدة البيانات، وقائمة الطلبات تستخدم صفحات (25 في الصفحة) وبحثًا خادميًا.
- إعدادات المطعم تشمل الحد الأدنى والوقت التقديري ونطاق التوصيل وساعات العمل، بجانب رسوم التوصيل وحالة الفتح.
- تعديل الطلب قبل التجهيز يدعم الكميات والحجم والإضافات المتاحة؛ ويمكن إعادة تجهيز طلب مُسلّم من المنيو الحالية بالأسعار الجديدة.
- تم تثبيت نسخ CDN في ملفات HTML، وبناء Tailwind وقت البناء بدل Play CDN. شعار الموقع موجود في `public/assets/hopa-logo.svg` ويُنسخ إلى `dist/assets/hopa-logo.svg`.
- تصدير CSV، طباعة إيصال، نسخ العنوان، وسجل أحداث الطلب داخل لوحة الإدارة.

## مهم قبل النشر

**هذه الحزمة لم تُطبّق على قاعدة Supabase الحية ولم تُختبر بإرسال طلب فعلي.** لا تعتبر النظام جاهزًا لطلبات حقيقية حتى يُطبّق الترحيل، وتُنشر Edge Function وتُضبط الأسرار، وتُنفذ اختبارات التكامل أدناه. لا تضع مفتاح `service_role` أو `sb_secret` في HTML أو `.env` المخصص للواجهة أو المستودع.

### 1) قاعدة البيانات الجديدة

1. أنشئ مشروع Supabase جديدًا أو بيئة اختبار.
2. افتح SQL Editor ونفّذ `schema.sql` كاملًا؛ يحتوي الملف على المخطط الأساسي وسياسات RLS وترحيل الحماية المضمّن في آخره.
3. نفّذ `seed.sql` لإضافة قائمة مبدئية. **راجع الأصناف والأسعار والإضافات ورسوم التوصيل مع المطعم قبل الإنتاج**؛ هي بيانات من الملفات السابقة وليست اعتمادًا نهائيًا للأسعار.
4. أنشئ مستخدم الإدارة في Supabase Auth، ثم أضف UUID الفعلي فقط إلى عضوية الإدارة:

   ```sql
   insert into public.admin_users (user_id)
   values ('ضع-UUID-مستخدم-الإدارة-هنا')
   on conflict (user_id) do nothing;
   ```

### 2) قاعدة موجودة بالفعل (اتبع المسار ده بدل إعادة تشغيل `schema.sql`)

1. **خذ Backup قبل أي SQL** وتأكد من نجاح استعادة النسخة في بيئة اختبار إن أمكن.
2. افحص `orders_status_check`، ودالة `create_hopa_order`، ودوال التتبع القديمة، وسياسات RLS الحالية. لو ترقية التتبع `tracking_upgrade.sql` لم تُطبّق على المخطط القديم، راجعها وشغّلها في نافذة صيانة؛ الملف يسحب إتاحة RPC القديمة للمتصفح.
3. طبّق `supabase/migrations/202610150001_production_hardening.sql` على قاعدة تتطابق مع المخطط الحالي. الترحيل داخل transaction: لو اكتشف حالة طلب قديمة غير معروفة سيتوقف ويرجع التغييرات بدل ما يطبّق جزءًا منها؛ افحص الحالات بقائمة `select distinct status from public.orders;` واربط القيم غير المعروفة صراحةً قبل إعادة المحاولة.
4. شغّل `supabase/tests/security_smoke_test.sql` بعد نجاح الترحيل.
5. انشر Edge Function حسب الخطوة التالية، ثم حدّث ملفات الواجهة إلى الإصدار المبني. توقّع نافذة صيانة قصيرة أثناء تبديل المسار القديم بالجديد، ولا تسحب RPC القديم قبل التخطيط لنشر البديل.

**الطلبات التاريخية:** الترحيل لا يولّد رموز تتبع جديدة للطلبات الموجودة، لأن ذلك قد يتيح الوصول غير المقصود إليها. الطلبات القديمة لن تعمل معها آلية رابط التتبع الجديدة؛ أدِرها من لوحة الإدارة أو ضع سياسة انتقال منفصلة بعد مراجعة خصوصية البيانات.

## 3) نشر Edge Function وتأمين الأسرار

ثبّت Supabase CLI محليًا، ثم من جذر المشروع:

```bash
supabase login
supabase link --project-ref cmbisckklhehdnltfdus
```

ولّد قيمة عشوائية طويلة (مثلاً `openssl rand -hex 32`) واضبط الأسرار على Supabase فقط. مثال بعد استبدال القيم بنطاق موقعك:

```bash
supabase secrets set HOPA_RATE_LIMIT_SALT="قيمة-عشوائية-طويلة-خاصة-بك" HOPA_ALLOWED_ORIGINS="https://example.com"
supabase functions deploy hopa-public-api
```

`HOPA_ALLOWED_ORIGINS` يقبل قائمة نطاقات مفصولة بفواصل عند استخدام أكثر من نطاق. لا تستخدم `*` على الإنتاج. دالة Edge تعتمد على متغيرات البيئة التي يوفرها Supabase (`SUPABASE_URL` ومفتاح الخادم)، ولا تحتاج إلى نسخ المفتاح السري داخل المشروع.

### إشعارات البريد (اختياري)

اضبط `RESEND_API_KEY` و`HOPA_NOTIFICATION_EMAIL` و`HOPA_NOTIFICATION_FROM` كأسرار للخادم فقط. إذا لم تضبط الثلاثة، يتوقف البريد وتبقى عملية إنشاء الطلب مستقلة عنه. يجب أن يكون عنوان `from` معتمدًا لدى مزود البريد.

### Cloudflare Turnstile (اختياري لكنه موصى به عند فتح الموقع للجمهور)

1. أنشئ Widget في Cloudflare Turnstile وأضف المفتاح العام للموقع في ملف `.env` محليًا:

   ```dotenv
   VITE_TURNSTILE_SITE_KEY=ضع_المفتاح_العام_هنا
   ```

2. اضبط `HOPA_TURNSTILE_SECRET` كسر في Supabase Function، ويمكن تحديد `HOPA_TURNSTILE_HOSTNAME` لفرض اسم النطاق.
3. أعد البناء وانشر `dist/`، ثم انشر Edge Function من جديد إذا تغيّرت الأسرار/الكود.

لا تضع سر Turnstile في الواجهة. لو تركت المفتاح العام أو السر غير مضبوط، يبقى Turnstile معطّلًا؛ يظل rate limiting مفعّلًا طالما ضُبط `HOPA_RATE_LIMIT_SALT` ونُشر الترحيل.

## 4) بناء الموقع

يتطلب Node.js حديثًا واتصالًا لتنزيل الحزم أول مرة:

```bash
npm install
npm run check:syntax
npm run build
npm run preview
```

ارفع **محتويات `dist/`** إلى استضافة الموقع، وليس ملفات المصدر فقط. يجب أن يكون كل من `index.html` و`admin.html` في جذر النشر مع `assets/hopa-logo.svg`. ملفات HTML تستخدم مكتبات Supabase JS وLucide بنسخ مثبتة من CDN؛ واجهة الطلب تحتاج اتصال إنترنت وSupabase. إذا كان CDN غير متاح فلن يمكن إرسال الطلب، لكن الواجهة تعرض رسالة بدل تعليق شاشة التحميل.

`.env.example` مخصص للمفتاح العام الاختياري فقط. أسرار الخادم تُضبط عبر `supabase secrets set`. لا تُرفع ملفات `.env` الحقيقية إلى Git.

## 5) اختبارات قبل فتح استقبال الطلبات

1. بعد تطبيق الترحيل، شغّل `supabase/tests/security_smoke_test.sql`; يجب أن ينتهي دون exception.
2. سجّل دخول مدير معتمد وغير معتمد؛ الثاني لا يجب أن يرى بيانات الإدارة.
3. أنشئ طلب اختبار وأعد إرسال نفس الطلب بنفس المفتاح؛ يجب ألا ينشئ صفًا ثانيًا، وأن يحصل صاحب الرمز نفسه فقط على تفاصيل الطلب.
4. جرّب رقم طلب صحيحًا مع رمز خاطئ ورقم هاتف معروف؛ يجب ألا يُرجع معلومات. جرّب تتبعًا متكررًا وتأكد من استجابة `429` بعد تجاوز الحد.
5. اختبر تعديل وإلغاء طلب بحالة `استلمنا طلبك`، ثم جرّب نفس العمليات بعد `بيتحضر`؛ يجب أن تُرفض من الخادم.
6. جرّب انتقالات الحالة: `استلمنا طلبك → بيتحضر → خرج للتوصيل → تم التوصيل`. يجب رفض القفزات وإعادة الطلب المكتمل لحالة سابقة.
7. جرّب إغلاق المطعم، والصنف المخفي، وحجم/إضافة غير صالحة، والحد الأدنى، وانقطاع الاستجابة بعد إنشاء الطلب.
8. أنشئ أكثر من 200 طلب في بيئة الاختبار؛ يجب أن يظل الملخص التاريخي كاملًا وتظل الصفحات تعمل.
9. اختبر العرض عند 320/360/390px، وإتاحة لوحة المفاتيح، والطباعة وتصدير CSV، وRealtime مع صفحة الإدارة مفتوحة، والبريد إذا تم تفعيله.

## هيكل المشروع

- `index.html`: متجر العميل.
- `admin.html`: لوحة الإدارة.
- `src/styles.css` و`tailwind.config.cjs` و`postcss.config.cjs` و`vite.config.js`: بناء الستايل والإصدار.
- `assets/` و`public/assets/`: شعار هوبا المستخدم في المنيو.
- `schema.sql`: تأسيس قاعدة جديدة، مع تضمين ترحيل الحماية للمخطط الجديد.
- `supabase/migrations/`: ترحيلات قواعد البيانات المرقمة.
- `supabase/functions/hopa-public-api/`: وسيط الطلبات العامة والتتبع والتعديل والإلغاء.
- `supabase/tests/security_smoke_test.sql`: فحوص صلاحيات ومكونات أمنية بعد الترحيل.
- `tracking_upgrade.sql`: ترقية RPC تتبع قديمة عند الحاجة فقط، لا تُشغّلها عشوائيًا على الإنتاج.
- `use_logo_for_all_products.sql`: تحديث اختياري لقيم `image_url` للمنتجات الموجودة؛ الواجهة الحالية تعرض الشعار مباشرة بالفعل.

## حدّ نطاق التنفيذ

تم فحص صياغة JavaScript داخل `index.html` و`admin.html` محليًا. لا تتصل هذه الحزمة بقاعدة Supabase المنشورة ولا تنفذ SQL أو تنشر Edge Function تلقائيًا. لذلك يلزم إتمام خطوات النشر والاختبارات الحية قبل وصف النظام بأنه جاهز للإنتاج.

**ميزات تجارية ليست مفعّلة بعد في هذه الحزمة:** الكوبونات والكومبو والولاء والتقييمات، التحقق عبر OTP، رسائل SMS/واتساب، رسوم تلقائية مختلفة لكل منطقة توصيل، والأدوار الفرعية للإدارة. تحتاج هذه الميزات قواعد عمل وأسعارًا وحدود استخدام ومزود خدمة عند اللزوم؛ نصّ نطاق التوصيل الحالي للعرض فقط، ولا يحسب رسومًا حسب المنطقة. لا تعتمد عليها كميزات منشورة.


## مراجع رسمية

- [Supabase Edge Function secrets](https://supabase.com/docs/guides/functions/secrets) — أسماء مفاتيح النشر والسرية التي توفرها المنصة.
- [Supabase background tasks](https://supabase.com/docs/guides/functions/background-tasks) — استخدام `EdgeRuntime.waitUntil` لإرسال إشعارات البريد دون تعطيل تأكيد الطلب.
- [Cloudflare Turnstile server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) — التحقق من رمز Turnstile على الخادم إلزامي؛ عنصر الواجهة وحده غير كافٍ.
- [Tailwind Play CDN](https://tailwindcss.com/docs/installation/play-cdn) — نسخة الإنتاج تبني CSS بدل تشغيل Play CDN داخل المتصفح.
